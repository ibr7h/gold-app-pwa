# ذهبك — بوابة الإدارة المستقلة

- التطبيق: `apps/admin/public/`
- المسار المخصص مستقبلًا: `/gold-app-pwa/admin/`
- الهوية الثابتة: `#001F3F` و `#C5A021` و `#D4AF37`.
- الدخول محصور بحسابات `admin`، ولا يوجد تسجيل ذاتي أو حساب افتراضي.
- الواجهة لا تحفظ رموز JWT في Local Storage أو Session Storage؛ رموز الدخول في الذاكرة فقط، وإعادة تحميل الصفحة تتطلب تسجيل دخول جديدًا.
- لا تُستخدم بيانات أو أرقام تجريبية في الواجهة.

## نطاق المرحلة الأولى

- نظرة عامة: إحصاءات المستخدمين والتجار والمديرين والموقوفين من `GET /admin/summary`.
- المستخدمون: استعراض مصفّى ومحدود الصفحات من `GET /admin/users` دون تعديل، وبحقول آمنة فقط.
- مراقبة السعر: آخر قراءة محفوظة من `GET /prices/latest` مع وقت الرصد والمصدر، وليس ادعاء سعر مباشر.
- اعتماد التجار، الدعوات، المسوقون، الاشتراكات، العمولات، التدقيق: تظهر كخدمات مستقبلية ولا تنفذ طلبات API وهمية.

## شرط تشغيل الميزة

يتطلب نشر واجهة الخادم المستقلة في الفرع `feature/admin-readonly-api-20261015` من مستودع `ibr7h/gold-app`. قبل نشر الخادم، سيعرض التطبيق رسالة بأن الخدمة غير منشورة دون إخفاء الخطأ.

## قبل الإنتاج

- مراجعة توافق الواجهة مع التصميم الأصلي من أرشيف UI.
- إجراء اختبار دخول فعلي بمدير، وتجربة رفض دخول حساب user/merchant، والتحقق من 401/403 من الخادم.
- مراجعة نهج جلسات المدير والإبطال الفوري للرموز وMFA قبل أي صلاحيات كتابة.
- إنشاء منظومة Audit Log غير قابلة للتعديل قبل اعتماد التجار أو إيقاف الحسابات أو تنفيذ أي إجراء مالي.
- لا تغيير على `apps/user` أو `apps/trader` أو رابط Render للإنتاج.

## استعادة التصميم الأصلي من UI.zip (2026-10-15)

المصدر المعتمد: الأرشيف الأصلي `UI.zip`، الملفات:
`screens/02_login_admin.html`, `18_admin_dashboard.html`, `19_admin_users.html`,
`20_admin_invites.html`, `21_admin_stats.html`, `22_admin_settings.html`,
`css/royal-theme.css`, `assets/icons/app_icon_admin.svg`.

استُعيدت الهوية البصرية (الخلفية الكحلية الأصلية، البطاقات البيضاء، الدرع الذهبي، الشريط السفلي بخمسة أقسام) مع **إزالة عناصر العرض التجريبية**، وأهمها حساب الإدارة الافتراضي، كلمة المرور، OTP غير الحقيقي، بيانات الحسابات الوهمية، رسوم التداول المفبركة ومفاتيح GoldAPI النصية.

الحسابات الحقيقية تُجلب فقط عبر `GET /admin/users` والملخص عبر `GET /admin/summary` بعد تحقق صلاحية المدير. لن تُفعّل أدوات تعديل المستخدمين والدعوات والإعدادات حتى تُنفذ في الخادم مع سجل تدقيق ومصادقة مناسبة.

لا تغيير في `apps/user` أو `apps/trader` أو Backend؛ حالة API تعتمد على الفرع المنفصل للخادم.

## الدخول الإلزامي بخطوتين

بعد إدخال البريد وكلمة المرور لا تصدر جلسة الإدارة بعد. يستخدم التطبيق
`POST /auth/admin/login` لإنشاء تحدٍ وإرسال رمز مكون من ستة أرقام بالبريد،
ثم `POST /auth/admin/verify` للتحقق وإصدار الجلسة فقط عند نجاح الرمز.
يمكن إعادة إرسال رمز جديد بعد المهلة عبر `POST /auth/admin/resend`.
لا تُحفظ كلمات المرور ولا رموز OTP في تخزين المتصفح. يجب نشر الخادم المحمي قبل واجهة المدير.

## إجراءات الحسابات وسجل التدقيق

تطبيق **Admin فقط**: يمكن للمدير الذي اجتاز رمز البريد إيقاف حساب مستخدم أو تاجر نشط وإعادة تنشيط حساب موقوف، بعد كتابة سبب (12–300 حرف)، تأكيد صريح، وإعادة إدخال كلمة مرور المدير. الخادم يتحقق من جميع الشروط ولا يثق بواجهة المستخدم. تُلغى جلسات الحساب ويرتفع إصدار بيانات اعتماده في معاملة PostgreSQL واحدة مع سجل التدقيق. يظل تغيير الأدوار، وحسابات المديرين، والحسابات المحذوفة خارج صلاحيات هذه المرحلة. تظهر آخر الإجراءات عبر `GET /admin/audit` للقراءة فقط. لا تُخزّن كلمة المرور إداريًا ولا تُرسل ضمن سجل التدقيق.

## إصلاح رؤية أزرار الحسابات (واجهة التحديث 8)

كل بطاقة مستخدم تعرض بوضوح «إيقاف» و«تنشيط»؛ يتفعّل أحدهما فقط إذا كان الحساب من نوع user/merchant وفي حالة active/suspended. حسابات admin والمحذوفة تعرض سبب تعطيل الإجراء بدلاً من إخفائه. الحذف النهائي غير متاح. يتضمن الإصلاح تخطي كاش JavaScript/CSS السابق باستخدام عنوان أصل جديد لكل إصدار، واستراتيجية network-first لهذه الأصول حتى على PWA المثبّت.

## تصحيح محاذاة البريد الإلكتروني الإداري (v9)

احتفظت الواجهة بأيقونة الحقل الأصلية إلى اليسار مع تخصيص `padding-left:50px` للنص حتى عندما يكون الإدخال `dir=ltr` داخل صفحة عربية RTL، بدل استخدام `padding-inline-end` الذي كان يحجز المسافة على يمين حقل البريد ويجعل الأيقونة تتداخل مع الحروف. ضُبطت تسمية الحقل على «البريد الإلكتروني الإداري» وأعيد إصدار ملفات الواجهة `admin-v9` لتجاوز كاش الآيفون. لا تغييرات في مصادقة المدير أو في تطبيق المستخدم والتاجر.
